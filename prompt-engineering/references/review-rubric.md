# 教学提示词评价与证据规则

本量表用于本项目的提示词探索，沿用项目实验计划的观察维度。它不是经过验证的学习效果测量工具。模板设计本身不产生数学实验、评分或核验通过记录。

## 一、数学核验

对每份实际生成的教学稿单独检查，原证明与教学稿分别报告。先列出本次真正检查的对象与证据，再记录判定。

| 检查对象 | 应核对的内容 | 证据与状态的写法 |
|---|---|---|
| 原题与原证明 | 题面全文、假设、定义域、结论、边界和等号条件 | 引用真实核验报告；没有报告则写“未核验／未记录” |
| 教学稿主推导 | 是否改动条件或结论；每步是否有依据；是否省略必要情形 | 标注实际回答位置与检查发现，不因文字流畅判为正确 |
| 错误提醒 | 被提醒的做法是否确实错误，原因是否适用于本题 | 必要时核查反例；未检查的内容明确列出 |
| 引导问题与答案 | 问题是否可回答、答案是否正确且与主推导一致 | 保存实际检查对象、结果和疑点 |
| 迁移练习及答案 | 条件是否完整、是否真的可用所总结的方法、答案是否正确 | 新增数学内容单独核验，未给答案时不虚构答案证据 |
| 图示、表格或小例子 | 数值、范围、对应关系是否正确；是否产生误导 | 记录实际检查；图像的直观性不能替代证明 |

客观字段分开记录：运行完成状态、工具检查结果、独立核验 verdict、人工参考判定。没有执行的检查写“未执行”，失败、超时与未通过保留实际状态。

工具证据应包含工具名称、输入假设、检查对象与结果；符号或数值工具只支持其实际检查的部分。独立核验 `correct` 是该模型检查流程的判定，不能写成 Lean 证明或数学保证。模型自查只能标为自查。

若教学稿引入未通过核验的改写推导、错误例子或练习，报告该限制，不列为已核验合格教学答案。发现原证明问题时回交正常数学工作流处理，不通过本套模板改动求解器、启动器或证明合同。

## 二、自动教学分析（需人工确认）

此处写可观察的表现与具体证据，不填写用户感受，不默认打分。每个维度至少给出实际回答中的位置、短引文或具体行为；没有做到或证据不足时明示。

| 维度 | 可观察证据 | 不能替代的结论 |
|---|---|---|
| 关键思路 | 是否解释选择某方法的理由，而不只列步骤 | 不据此声称学生已经理解 |
| 逐步引导 | 是否指出困难步骤并给出可回答的中间问题 | 不把 AI 自问自答当作学生独立作答 |
| 条件与错误提醒 | 是否指出本题相关条件与真实错误，并解释原因 | 不把泛化提醒当作已避免学生错误 |
| 方法总结与迁移 | 是否给出方法适用条件及可迁移练习 | 不把练习存在当作迁移学习成功 |
| 知识匹配 | 概念是否在学生已学列表，未学概念是否解释 | 背景未知时不能断言匹配学生 |
| 语言整理 | 是否精炼、去重、衔接清楚，必要步骤是否保留 | T3 字数减少不等于教学质量提高 |
| 直观表达 | 图示、表格或例子是否准确对应推理 | 没有需要时不因缺图自动判低质量 |
| 多智能体与工具分工 | 实际哪个角色完成求解、核验、修订，工具查了什么 | 不补写未发生的协作或修补过程 |

`manifest.task_review` 是字符串，写入以上依据实际回答形成的分析，记录程序会标为“自动检查说明（需人工确认）”。建议格式：

```text
版本与证据：<iteration_id；实际回答／检查证据路径>
关键思路：<具体证据或未做到>
条件与错误提醒：<具体证据或未做到>
通用方法与引导：<具体证据或未做到>
语言与直观表达：<具体证据或未做到>
知识范围：<与已学／未学对照；未知处>
数学与分工限制：<实际核验范围、未核验新增内容、实际协作>
需人工确认：以上为自动分析；尚无用户阅读感受或学生学习测验证据。
```

版本比较依据实际输出描述“增加了哪些内容／仍缺什么／发生了什么错误”。T0—T2 固定共同输入与运行设置；T2 新增多项要求属于同一个教学支架包，不能单独推断某项要求的因果效果。T3 是依赖 T2 的后处理，单独报告。未作统计对照时不报告普遍错误率下降百分比。

## 三、人工评价

默认使用独立 `人工评价.md` 的自由文字，由用户提供。姓名、感受、偏好与分数留空或标“待填写”，不得从自动分析转填为人工评价。

可由用户自愿采用项目实验计划中的 0—2 分量表：0＝没有或明显不合适，1＝有但不足，2＝清楚且适合学生。评分维度为关键思路、逐步引导、知识匹配、常见错误、方法总结、表达与直观性；每项由评价者写一句理由。该量表不改变项目默认的自由文字人工评价方式。

没有真人完成迁移练习时，仅记录阅读感受与文本观察。若用户提供实际学习测试，保存测试任务、作答与评价证据，再说明能支持到何种结论。
