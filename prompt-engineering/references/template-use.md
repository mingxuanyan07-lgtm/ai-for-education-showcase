# 教学模板使用说明

## 适用与边界

本目录只提供证明完成后的教学提示词。用户明确要求提示词设计、教学整理或教学版本对照时使用；普通数学题继续依照根 `AGENTS.md` 的实际求解流程执行。不把本模板放入 Rethlas 题面或两个角色的提示词，不改变求解模型、推理强度、搜索策略、轮次、服务、安全设置或自动归档钩子。

设计、读取、修改模板以及检查占位符不调用模型，也不创建真实实验记录。没有收到实际对照运行要求时，保存设计成果即可。文件中的占位符与格式片段不是待解数学题。

## 组装提示词

1. 从已经完成的求解记录读取完整题面、原证明及真实核验信息，保留原始文件。没有通过依据时不能称为“已核验证明”，也不能据此启动正式的教学对照。
2. 填写 `../prompts/common-input.md`。未知学生背景明确标“未知”，没有必要仅为背景缺失重问用户；缺少影响数学答案的条件则按照项目规则澄清。
3. T0、T1、T2 分别用同一份共同输入追加 `teaching-t0.md`、`teaching-t1.md`、`teaching-t2.md` 的正文，在彼此独立的上下文中生成。不要把先前版本回答或评价交给后一版本。
4. T3 仅使用实际 T2 原文，保留共同输入，追加 `teaching-t3.md`。记录其对 T2 的依赖，不当作独立样本。
5. 正式运行前保存每份展开后的完整实际 prompt。生成后原样保存回答，再按 `review-rubric.md` 分开进行数学检查、自动教学分析与用户人工评价。

T0—T2 的唯一比较因素是累计增加的教学要求；共同输入、模型、推理强度、工具权限及其他可控设置固定。T1 只增加关键思路与选择理由。T2 增加项目实验计划规定的教学支架包；该包内部多项要求尚未分别控制。如需研究某一项的独立作用，另行设计对照，不改写已有版本的历史 prompt。

模型信息来自实际运行元数据；获取不到时写“未记录”。教师或研究者参考答案不作为求解者资料；若另行提供给教学整理，应在实际共同输入中明确保存，且各版本一致。

## 与现有记录接口衔接

本说明不安装工具、不运行脚本。用户授权实际生成或对照后，按 `../../docs/自动记录与打包.md` 的现有 manifest 接口保存与归档。

- 已有求解后的教学整理沿用原 `question_id`、`ai_id`、`run_id`，采用新的稳定 `iteration_id`，例如 `teaching-t0-v1`、`teaching-t1-v1`、`teaching-t2-v1`、`teaching-t3-v1`。这些版本是同一次记录中的提示词迭代，不伪装为独立重测。
- 若明确安排另一种 AI 或独立重测，按项目规则另设真实身份与 UTC 时间加随机后缀的 `run_id`，不能将另一模型的回答冒填为原工作流。
- 保存实际 `prompt_file`、`answer_file` 及真实检查材料；改动提示词时保留旧版本并增加新 `iteration_id`。T3 的记录注明使用哪个 T2 iteration。
- `verification`、`tool_checks` 保存客观数学检查；`task_review` 保存需人工确认的教学证据分析；`human_review` 只导入用户明确提供的原话。不要将自动分析写进人工感受。
- 共享索引与 ZIP 交给现有 `scripts/experiment_records.py` 更新。没有实际成功调用并确认结果时，不能称为已记录或已打包。

## 静态验收

模板交付只检查：共同输入完整、T1 保留 T0 正文、T2 保留 T1 正文、T3 依赖标记清楚、未知背景与数学检查规则一致、人工评价未被预填。此验收不表示模板已经提高教学效果，也不代表完成了一次数学模型测试。
