# 知识准备与解题主线 v1

这是新增教学合同的设计资产，基线 T0—T3 保持原样。针对用户提出的知识清单、前置要求和解答主线缺陷；预期改进尚待真实教学评测。模板本身不构成数学题求解请求，也不产生实验样本。

与 `common-input.md` 组装后使用，实际题面、已核验证明及学生背景必须展开。当前默认 DeepSeek 流程已有显式可选的 `knowledge-route-v1` 实现；读取本文件不会自动启用或调用模型。

```text
请把已核验的证明整理成适合阅读的中文教学解答。

在展开推导前，简明说明本解法的知识准备：每项知识需要会什么、必要含义或公式和适用条件、在本题哪一步使用。只列实际依赖，区分必要知识与可选扩展；本题要证明的新结论不能作为前置要求。

学生已学／未学信息只取自共同输入，缺失时明确未知。知识清单是解法要求，不是学生能力诊断。涉及明确未学的知识时，优先用已学内容解释或改写；无法做到时说明还需补什么及原因。

先用简短连贯文字交代目标、关键困难、选择该方法的理由，以及各步怎样通向结论，再展开证明。一步题不凑步骤，多问题交代各问之间的依赖。

关键步骤分别说明目的、依据、所得结果和后续用途，使正文对应前面的路线。必要的定义、定理条件和关键理由就在使用处交代，较长基础解释放按需补充并给出指引。保持完整证明，避免无关扩展和重复叙述打断主线。

原题条件、数学结论和用户明确指定的结构、篇幅优先；上述要求融入相应形式，不机械要求固定标题或表格。不填写人工感受，不声称已经提升学习效果。
```

独立检查须覆盖：实际知识及用途、前置掌握程度、背景是否忠于用户、路线是否解释方法选择、步骤是否与路线对应、主线是否连续且保留必要依据。每项写实际稿件引文和理由；没有做到或证据不足时明示。数学核验与教学检查分别报告，不按标题、关键词数量或篇幅直接判定通过。后续对照固定模型、原题、证明、学生背景和预算；修改后重新外审，历史报告不覆盖。
